# Argon2 비밀번호 해시와 단기 Bearer 토큰

## 상황

첫 `users` 테이블은 있지만 계정을 만들거나 요청한 사용자를 식별할 방법이 없었다. 이후 노트 API에서 소유권을 확인하려면 재사용할 수 있는 인증 의존성이 필요하다.

## 결정

이메일을 앞뒤 공백 제거·소문자 변환 후 유일한 계정 식별자로 저장한다. 비밀번호는 `pwdlib`의 권장 Argon2 설정으로 해시한다. 로그인 성공 시 사용자 ID(`sub`)와 만료(`exp`)를 담은 HS256 JWT를 발급한다. 유효 기간은 30분이며, 비밀 키는 환경 변수 `AUTH_SECRET_KEY`로 주입한다. 인증 요청은 서명·만료를 검증하고 DB에서 해당 사용자를 다시 조회한다.

## 이유

기존 `users` 스키마를 유지하면서 비밀번호 원문을 저장하지 않고, 이후 API에서 동일한 사용자 조회 의존성을 사용할 수 있다. 짧은 토큰 만료는 별도 세션 테이블 없이 장기간 유효한 자격 증명을 피한다.

## 고려한 대안

- 서버 측 세션: 즉시 로그아웃과 폐기는 편하지만 세션 저장소와 정리 절차가 필요하다.
- 장기 JWT·갱신 토큰: 잦은 로그인은 줄지만 탈취 후 유효 기간과 갱신·폐기 로직이 늘어난다.
- 비밀번호를 표준 해시 함수로 직접 구현: Argon2의 작업 비용 설정과 검증을 직접 관리해야 한다.

## Trade-off

발급된 토큰은 만료 전 개별 폐기할 수 없으며, 비밀 키를 교체하면 기존 토큰이 모두 무효화된다. 이메일 주소의 소문자 변환은 서비스의 계정 정책이므로, 대소문자를 구분하는 메일 서버의 주소를 별개 계정으로 취급하지 않는다. 인증 실패 횟수 제한, 이메일 확인과 비밀번호 재설정은 아직 없다.

## 다시 검토할 조건

로그아웃·강제 폐기·장기 로그인 요구가 생기거나 실제 인증 남용이 관측되면 세션 또는 갱신 토큰, 요청 제한 정책을 검토한다.
